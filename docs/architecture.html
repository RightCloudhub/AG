知识数据流

图谱抽取与 API 文档上传后的搜索索引是两条不同的路径。

图谱构建 · CLI / 知识管线

将语料转成通过校验、可追溯的结构化关系。

文档 / chunk→ 逐块抽取→ schema / confidence gate→ 实体解析→ 增量冲突处理→ GraphStore
复核分支：歧义或置信度差距不足 → ReviewQueue → 人工 approve / reject / skip。抽取任务支持 journal、retry 与 quarantine。

文档上传 · API 后台索引

上传内容作为文档与检索 chunk；当前不会在此流程中自动抽取图关系。

POST /v1/docs→ JSONL TaskStore→ 手动运行 Worker→ DocStore→ chunk → Vector / BM25
当前边界：仅 UTF-8 .md / .txt；最多 20 个文件/批、5 MiB/文件；API 不会自动启动 worker。

运行模式与基础设施

离线是默认值；模型与存储可独立切换。

Offline · 默认

MockLLMProvider、确定性离线答案规则、内存图/向量、BM25 与文件型文档。无需 API Key、Docker 或外部服务，适合本地开发和可复现评测。

Live · 显式启用

AGR_ALLOW_LLM=1 启用真实 LLM；AGR_USE_LIVE_STORES=1 切换 Neo4j / Qdrant。两项独立；BM25 与文件型 DocStore 仍由本地实现提供。

离线启发式服务演示语料，不是 Live LLM 的回答路径。

横切能力与运维入口

围绕查询、知识操作和发布评测提供治理与诊断能力。
