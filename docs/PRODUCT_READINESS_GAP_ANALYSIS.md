# 产品级交付差距评估

**评估日期：** 2026-09-23  
**对象：** AgenticGraphRAG 仓库当前实现  
**比较口径：** 与成熟知识库/RAG 产品的用户闭环和运行保障能力比较，不是算法性能排名，也不表示必须复制竞品功能。

## 结论

本项目已有扎实的工程底座：离线可复现、多路检索与多跳推理、API Key/RBAC、租户过滤、预算、审计、结构化日志和指标。距离**可交付产品**的主要差距是：业务用户不能独立完成“接入知识 → 看处理状态 → 验证检索 → 管理更新/复核 → 观察质量与运行”；另外，真实业务效果、线上延迟和多副本运行仍缺少正式验证。

这不是“缺少 Agent”的问题，而是从开发者工具/试用系统向操作闭环完整、运行结果可验收的产品收口。

## 对照基准

本文参考 RAGFlow、Dify 等产品官方资料中可见的知识运营能力：RAGFlow 描述了可配置的 Parser、Transformer、Indexer 处理管线；Dify Knowledge API 提供知识库文档管理、分段操作和检索接口。它们仅用于说明产品闭环的常见形态，不据此断言其答案质量优于本项目。来源见[资料与边界](#资料与边界)。

## 建议交付门槛

### M0：可控试点

- 由业务方确认一个目标领域、授权语料和问题范围；真实 heldout 金标含答案、证据及无答案案例，并由领域人员签字。
- 至少支持该领域实际使用的文件格式；上传后能在 UI 查看任务状态、失败原因、重试结果和索引版本。
- 一个文档版本能追踪到 chunk、图事实和答案引用；更新/删除后旧内容不会继续被检索。
- staging 上用真实后端运行跨租户回归、故障恢复和负载测试；明确 P95、错误率、引用支持率及单问成本门槛。
- 复核批准/拒绝有执行结果、操作者、时间和幂等记录，而非只有队列状态变化。

### M1：生产化

- 摄取队列具备共享持久化、租约/重试与多副本恢复；存储、向量索引、配置及审计均有备份和恢复演练。
- 角色化控制台具备知识管理、复核、检索验证、查询追踪和审计回查；关键操作有 RBAC、审计与租户边界测试。
- Prometheus/OTel 数据接入实际 collector 和告警系统；runbook 明确常见故障、升级、回滚及数据恢复。
- 根据客户身份源与数据隔离要求补 SSO、文档级 ACL、租户物理隔离等能力；明确哪些属于应用保证、哪些由部署环境保证。

### M2：可复制产品

- 支持可配置的解析/分块管线、索引版本、增量重建、批量管理和多知识库检索；优先覆盖真实客户文档，而非追求格式数量。
- 有可重复的回归与发布门禁，按领域/问题类型输出检索、答案、证据、延迟、成本和错误趋势。
- 通过实际用户试点确认权限模型、审计保留、数据导出/删除、容量和支持流程，再决定是否引入更多全局图检索、连接器或异步查询作业。

## 不应误判为缺失的能力

- 本项目已有 API RBAC、租户数据过滤、预算、审计事件、结构化日志、Prometheus 和可选 OTel 工程实现；主要差距是生产环境联调、告警/值班闭环和部署边界验证。
- 本项目已有 Agent 多跳、图/向量/BM25 混合检索、增量冲突处理和人工复核队列；差距在领域验收、上传到图谱的完整通路以及复核结果真正执行。
- 离线确定性是本项目的重要优势，应保留为测试/开发基线，不应把它误作线上 LLM 效果证据。
